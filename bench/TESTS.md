# Поток приложения и набор тестов

Документ описывает **что именно происходит внутри** и **как это проверять**. Он написан под наш
поток, а не под типовой чеклист офлайн-приложения: у нас нет сервера, нет синхронизации, нет
учётной записи и нет очереди отправки на сервер. Почему типовой чеклист к нам применим лишь
частично — в §2.

Правило то же, что во всём проекте: **число либо измерено на телефоне, либо помечено как
неизмеренное**. Ожидаемые результаты ниже, где они числовые, взяты из `results/`.

## 1. Поток

### 1.1. Что откуда берётся и куда ложится

```
                 ┌──────────── вход ────────────┐
   микрофон ────▶│ захват 16 кГц ─▶ очередь ─▶ VAD│
                 └──────────────┬───────────────┘
   снимок 📷 ─▶ OCR/облако ─┐   │ своя нарезка (подпор 1000 мс, хвост 300 мс,
   клавиатура ⌨ ───────────┤   │  порог +6 дБ над фоном, минимум речи 250 мс,
                           │   ▼  выдержка 600 мс)
                           └─▶ processText(dir, текст, авто, фильтр, kind)
                                  │
                                  ├─ язык реплики  → направление (pt2ru / ru2pt)
                                  ├─ свои слова (WordList) → подстановка
                                  ├─ маски (TextRules) → числа, цены, адреса → XQ1…
                                  ├─ словарь (Phrasebook): пины → затравка → корпус
                                  ├─ иначе MT (OPUS-MT int8), по предложениям и строкам
                                  ├─ снятие масок, pt-BR правила, удаление <unk>
                                  ▼
                        ┌─────────┴──────────┐
                  экран (сразу)        очередь озвучки
                  запись в разговор    (ждёт holdMs тишины)
                                             ▼
                                       TTS → AudioTrack
```

Направление **не задаётся заранее**: оно выводится из языка самой реплики. Кнопки «Слушать PT» /
«Слушать RU» только сужают, что принимать; удержание принимает любой язык.

### 1.2. Состояния микрофона

| Состояние | Когда | Что происходит |
|---|---|---|
| закрыт | ни одна кнопка не нажата | `AudioRecord` не создан, точки записи в системе нет |
| слушает | включена «Слушать PT» и/или «Слушать RU» | захват + VAD + конвейер |
| удержание | палец на PTT | захват идёт в отдельный буфер, VAD не участвует |
| заглушён | идёт озвучка в динамик | `muteUntil`; при выводе в наушник **не глушится** (протечка −13…+0,1 дБ) |

### 1.3. Что лежит на устройстве

Всё в `Android/data/app.falar/files/`:

| Файл | Что | Кто пишет |
|---|---|---|
| `chats/<id>.json` | разговоры: реплики (`dir, src, dst, at`, необязательно `fixed`, `by` — user/cloud/llm, `who`), имя, тема `topic`, глоссарий `terms`, признак улучшения | после каждой реплики; уточнитель; облачный пересмотр; правка реплик человеком |
| `models/learned.json` | выученные фразы и счётчики повторов; с 0.20 — и правки перевода от облака/уточнителя (`by`) | `Phrasebook.record`, `Phrasebook.fix` |
| `models/phrasebook_user.json` | пины — только ручные, ключ и перевод в маскированном виде | «запомнить», «исправить перевод» |
| `models/cache/*.wav` | кэш звука выученных фраз | `Phrasebook.putAudio` |
| `known_words.json`, `word_ru.json` | известные слова и переводы отдельных слов | вкладка «Изучение» |
| `models/speaker_profiles.json` | слепки голосов | режим «голоса» |
| `models/openrouter.json` | ключ, список бесплатных моделей, подтверждение цены, статистика маршрута | настройки и каждый облачный запрос |
| `at.log`, `at.tsv` | журнал для человека и машинный журнал сегментов | всегда |
| `models/.verified.json` | кэш проверок моделей: размер, mtime и sha256 сверенных файлов — чтобы не хэшировать 3 ГБ при каждом старте | загрузчик моделей (0.21) |
| `models/**/*.part` | недокачанные файлы; следующий запуск продолжает с их длины (`Range`) | загрузчик моделей |
| в APK: `assets/models_manifest.json` | копия `models/manifest.json` — что и откуда качать, sha256 каждого файла; `build.sh` сверяет её с версией приложения и с файлами из репозитория | сборка |

### 1.4. Где вообще используется сеть

Три места; автоматически — только то, что явно включено:

1. **название разговора** — при уходе из разговора длиннее двух реплик, если у него ещё нет темы;
2. **пересмотр разговора** — кнопка «получше» или интервал в репликах из «Системы» (по умолчанию
   выключен); уходит разговор целиком в пределах 6000 знаков с конца, включая реплики собеседника,
   после одноразового согласия;
3. **текст со снимка** — пока офлайн-распознавание не подключено;
4. **загрузка моделей** (0.21) — по манифесту из APK с Hugging Face и релизов sherpa-onnx: обязательное
   (2,0 ГБ) с экрана первого запуска по кнопке, необязательное из «Системы» по выбору. По умолчанию
   только по сети без учёта трафика (Wi-Fi); «качать и по мобильной сети» — тумблер. Каждый файл
   сверяется по sha256, докачка после обрыва с того же места. Никаких данных наружу: только GET.

Плюс разовый запрос каталога моделей, чтобы подтвердить **нулевую цену** и возможности.
Без сети приложение обязано работать целиком, кроме этих четырёх пунктов; кнопка «получше» без сети
делает локальный проход, если включён контекст 🧠.

## 2. Почему типовой офлайн-чеклист применим частично

| Пункт типового чеклиста | Применимо? | Наш аналог |
|---|---|---|
| Синхронизация офлайн→онлайн | **нет** | нечего синхронизировать: сервера нет, данные наружу не уходят |
| Идемпотентность запросов | **частично** | облачный запрос не повторяется автоматически; перебор идёт по разным моделям, а не повторяет ту же |
| Очередь отправки (outbox) | **да, но другая** | очередь **озвучки** (`sayQ`): порядок и принадлежность разговору |
| Конфликт «локальное старее» | **нет** | единственный писатель — само приложение |
| Конфликт «удаление vs редактирование» | **да** | фоновый уточнитель держит копию разговора и пишет её целиком, пока человек правит реплики |
| Миграция схемы БД | **да** | наши форматы на диске; правило версионирования именно об этом |
| Лимит места | **да** | модели 1,4 ГиБ, кэш звука и разговоры растут |
| Очистка кэша ОС | **да** | проверить, что чистится только `models/cache`, а не разговоры |
| Шифрование локальной БД | **да, и это нерешено** | разговоры лежат открытым текстом, см. §5 |
| Мерцающая сеть, пакетные потери, 2G | **частично** | только для трёх облачных операций |
| Индикация сети | **да** | почему «получше» недоступно — в строке-подсказке на экране разговора (0.20) |
| Exponential backoff | **частично** | автоматический пересмотр по интервалу удваивает интервал после 429 или обрыва до ручного нажатия; ручные запросы не повторяются |
| Фоновое энергопотребление | **да** | сервис держит wake lock и микрофон |

## 3. Тесты

Обозначения: **[изм]** — проверено на телефоне, число в `results/`; **[код]** — проверено только
сборкой/кодом; **[нет]** — не проверялось.

Стендовые интенты подаются через активность:
```bash
adb shell am start -n app.falar/dev.agenttranslator.MainActivity --es <ключ> '<значение>'
```
С 0.20 добавлены: `edittext '<индекс>|<текст>'` (правка исходника реплики), `edittrans
'<индекс>|<текст>|pin'` (правка перевода, `pin` — закрепить), `refineevery N`, `cloudevery N`
(0 — по кнопке), `consent 1` (согласие на отправку разговора), `clearterms 1`, `translit '<фраза>'`.

### Принятый риск, решение за человеком

- **Разговоры лежат открытым текстом** в `Android/data/…/chats/*.json`: с root или adb читаются целиком.
  Варианты — шифровать ключом из Android Keystore, перенести во внутреннюю память (`getFilesDir()`),
  либо признать риск явно.

  **Отложено 17.09.2026 до того, как проект окажется в git**: формат хранения не менять раньше,
  чем появится история. Ниже — что планировалось и что добавила сверка с кодом, чтобы разговор
  потом начать с этого места.

  *Планировалось:* AES-256-GCM ключом из `AndroidKeyStore` (псевдоним `at.data`, без требования
  разблокировки — иначе фоновая служба не сможет писать); файл = магия `ATE1` + IV 12 байт +
  шифротекст; шифруются `chats/*.json`, `known_words.json`, `word_ru.json`, `models/learned.json`,
  `models/phrasebook_user.json`, `models/speaker_profiles.json`, `models/wordlist.json`;
  `Phrasebook`, `Speaker`, `WordList` переходят на `Chats.read/write`; миграция при старте по магии
  со счётчиком в журнале, версия по MINOR; стендовый интент `--es dumpchat` для чтения с ПК;
  испорченный или нерасшифрованный файл пропускается, не роняя список.

  *Что показала сверка с кодом (учесть при возврате):*
  - Шифровать одни файлы бессмысленно: каждая реплика с переводом пишется в `at.log`, `at.tsv`,
    logcat и в текст уведомления (`notify(asr + " → " + mt)`), видимость которого на экране
    блокировки не задана. Обещание «без запуска приложения разговоры не прочитать» выполнимо,
    только если текст реплик в журналы идёт под стендовым флагом (в `prefs`, с предупреждением
    в «Системе»), а без флага пишутся метки, тайминги и длина текста; уведомление показывает
    только состояние.
  - В манифесте нет `android:allowBackup="false"`: автобэкап Google по умолчанию берёт
    `getExternalFilesDir()` целиком, включая `models/openrouter.json` с ключом; сегодня спасает
    лишь то, что модели превышают квоту бэкапа.
  - Ключ Keystore напрямую на файлах медленный по устройству: каждый кусок данных идёт через
    Binder в TEE, а `Chats.list()` читает все файлы целиком в потоке интерфейса. Стандартная
    схема — ключ Keystore заворачивает случайный ключ данных, лежащий в файле, а файлы шифруются
    им в процессе через `javax.crypto`. Это же даёт выгрузку `--es dump all` всех шести файлов
    и переносимость накопленного между Redmi и POCO. Цифру снять на телефоне до выбора схемы.
  - Потеря ключа при переустановке совпадает с удалением каталога `Android/data`, поэтому
    отдельный риск остаётся только у ручных копий, и его закрывает выгрузка.
  - `models/cache/*.wav` остаются открытыми (разбор по смещению 44 в `Phrasebook.audio`):
    README должен называть это прямо, плюс кнопка «очистить кэш звука».
  - Кэш списка разговоров и частот слов (`Chats.list()`, `Learn.top()`) сделать до шифрования,
    иначе расшифровка ляжет на поток интерфейса.

### Не исправлено, требует отдельной работы

- при достижении потолка в 500 реплик закрытый разговор не отправляется на улучшение и именование.

Закрыто в 0.20: реплика на лету при смене разговора (номер снимается до распознавания), разбор
разговоров в потоке интерфейса (кэш по отпечатку файлов, рабочий поток), «получше» без сети
(причина в строке-подсказке, локальный проход при включённом контексте).
