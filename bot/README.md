# Бот обратной связи Falar

Сообщения людей из приложения и с сайта он передаёт разработчику. Бот работает на Cloudflare
Workers: своего сервера нет. Telegram сам присылает каждое сообщение боту (webhook), а данные
лежат в базе D1, это SQLite у Cloudflare. На бесплатном тарифе — 100 тысяч запросов в сутки.

Код написан по правилам [Telegram Serverless](https://core.telegram.org/bots/serverless): модули
импортируются голыми именами, есть `api` и `db` из `sdk`. Serverless в октябре 2026 года был в
закрытой бете, переключателя в @BotFather не было. Когда откроют, `handlers/`, `lib/` и
`schema.js` переедут туда без правок; меняется только прослойка `cf/`.

## Как устроено

- Человек пишет боту в личку. Приложение открывает чат с готовым текстом. Первая строка — метка
  `#перевод`, `#ошибка` или `#идея`, затем версия и модель телефона
  (`bench/apk/src/dev/agenttranslator/Feedback.java`).
- Бот кладёт копию в закрытую группу разработчика с топиками. По метке сообщение попадает
  в «Переводы», «Ошибки» или «Идеи». Сообщение без метки идёт туда же, куда предыдущее сообщение
  того же человека, если с него прошло не больше получаса, иначе в общий топик. Топик «Задачи» —
  для своих задач, бот туда не пишет. Пока группы нет, копии приходят разработчику в личку.
- Разработчик отвечает (reply) на копию, и бот пересылает ответ человеку. `/block` или `/unblock`
  ответом блокирует или возвращает человека.
- От одного человека — не больше 15 сообщений за 10 минут. На первое лишнее бот отвечает
  предупреждением, дальше молчит.
- В базе хранятся имя человека, счётчики и номера сообщений (какая копия кому принадлежит).
  Текстов в базе нет.

| Файл | Что |
|---|---|
| `handlers/message.js` | всё поведение бота |
| `lib/feedback.js` | правила без сети и базы: метка → топик, подпись, частота, тексты |
| `lib/store.js` | база: голый SQL с `:именами` |
| `lib/owner.js` | id разработчика, приходит из секрета `OWNER` |
| `schema.js` | таблицы |
| `cf/worker.js` | Worker: принимает webhook на `/telegram`, проверяет секрет в заголовке |
| `cf/sdk.js` | `api` (Bot API через fetch) и `db` (D1, `:имя` → `?N`) |
| `cf.sh` | вход, токен, развёртывание, статус |

## Данные бота — вне репозитория

Файл `~/.config/falar/bot.env` (права 600). Его пишет и читает `cf.sh`:

```
BOT_TOKEN=…          # токен бота из @BotFather (cf.sh token, скрытым вводом)
WEBHOOK_SECRET=…     # создаётся сам: им Telegram подписывает запросы к Worker
FALAR_BOT_OWNER=…    # ваш Telegram id (cf.sh owner)
CF_D1_ID=…           # номер базы D1, BOT_URL=… — адрес Worker (пишет cf.sh deploy)
```

Секреты Worker (`BOT_TOKEN`, `WEBHOOK_SECRET`, `OWNER`) уходят в `wrangler secret bulk` через
stdin, а в Bot API — из файла (`cf/tg.mjs`). В командные строки, в репозиторий и в чат они не
попадают. Номер базы — данные аккаунта, поэтому `wrangler.jsonc` собирается из
`wrangler.template.jsonc` и в git не лежит.

## Запуск с нуля

1. @BotFather: `/newbot` → имя «Falar», username `falar_tbot`.
2. Бесплатный аккаунт на dash.cloudflare.com. Затем `bash bot/cf.sh login`: откроется браузер,
   разрешите доступ.
3. `bash bot/cf.sh token` — скрипт спросит токен бота и покажет его @username.
4. `bash bot/cf.sh deploy` — создаёт базу и таблицы, загружает код и секреты, ставит webhook.
   Повторяйте после правок кода. Новый адрес *.workers.dev отвечает не сразу: сертификат HTTPS
   выпускается минуты. До тех пор Telegram держит сообщения у себя (`status` покажет очередь и
   ошибку TLS) и доставит их, как только адрес заработает.
5. Напишите боту `/id`, затем выполните `bash bot/cf.sh owner <число>`.
6. Создайте закрытую группу, включите в ней «Темы» и добавьте бота администратором с правом
   «Управление темами». Напишите в группе `/setup` — бот создаст топики. Повторный `/setup`
   ничего не ломает: он заново создаёт только удалённые топики.

`bash bot/cf.sh status` показывает, что видит Telegram: адрес webhook, очередь и последнюю ошибку.
`bash bot/cf.sh tail` показывает живой журнал Worker.

Команды разработчика: `/setup` (в группе), `/id`, `/help`; ответом на сообщение — `/block`
и `/unblock`. Если разработчик пишет боту в личку сообщение с меткой, бот обрабатывает его как
сообщение от человека. Так приложение проверяется своим аккаунтом.

## Проверки

- `cd bot && npm test` — на столе. Вместо Bot API — заглушка, база — та же SQL на node:sqlite,
  таблицы строятся из `schema.js` тем же кодом (`cf/dsl.mjs`), что и для D1. Прослойка `cf/sdk.js`
  проверяется против поддельного fetch.
- `cd bot && npm run e2e` — бот целиком в настоящей среде Workers: `wrangler dev --local`
  с локальной D1 против поддельного Bot API (`test/fake-telegram.mjs`). Аккаунт и сеть не нужны.

Новые столбцы в таблицах `deploy` сам не добавит: `CREATE TABLE IF NOT EXISTS` не меняет
существующую таблицу. Нужен `ALTER TABLE` через `wrangler d1 execute`.

Если понадобится трекер (Linear и т. п.): Worker умеет исходящий `fetch`, ключ — ещё одним
секретом из `bot.env`.
