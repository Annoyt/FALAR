# Бот обратной связи Falar

Сообщения людей из приложения и с сайта он передаёт разработчику. Бот работает в облаке Telegram
([Telegram Serverless](https://core.telegram.org/bots/serverless)): своего сервера нет, а обычного
токена бота код не знает, потому что платформа сама вызывает Bot API от имени бота.

## Как устроено

- Человек пишет боту в личку. Приложение открывает чат с готовым текстом. Первая строка — метка
  `#перевод`, `#ошибка` или `#идея`, затем версия и модель телефона
  (`bench/apk/src/dev/agenttranslator/Feedback.java`).
- Бот кладёт копию в закрытую группу разработчика с топиками. По метке сообщение попадает
  в «Переводы», «Ошибки» или «Идеи». Сообщение без метки идёт туда же, куда предыдущее сообщение
  того же человека, если с него прошло не больше получаса, иначе в общий топик. Топик «Задачи» —
  для своих задач, бот туда не пишет. Пока группы нет, копии приходят разработчику в личку.
- Разработчик отвечает (reply) на копию, и бот пересылает ответ человеку. `/block` или `/unblock`
  ответом блокирует или возвращает человека.
- От одного человека — не больше 15 сообщений за 10 минут. На первое лишнее бот отвечает
  предупреждением, дальше молчит.
- В базе бота хранятся имя человека, счётчики и номера сообщений (какая копия кому принадлежит).
  Текстов в базе нет.

## Данные бота — вне репозитория

Файл `~/.config/falar/bot.env` (права 600):

```
TGCLOUD_TOKEN=app…:…     # @BotFather → бот → Serverless → CLI Access → Access token
FALAR_BOT_OWNER=…        # ваш id в Telegram: бот присылает его в ответ на /id
```

Обычный токен бота (`123:ABC…`) здесь не нужен. `bash bot/tg.sh <команда>` делает три вещи:

- берёт токен только для этой команды; если токена нет, спрашивает его скрытым вводом и сохраняет
  в файл;
- пишет `lib/owner.js`, который не попадает в git;
- запускает `@tgcloud/cli` из `node_modules`. Через `npx tgcloud` запускать нельзя: без установки
  npx скачал бы посторонний пакет с именем «tgcloud».

## Запуск с нуля

1. В @BotFather: `/newbot` → имя «Falar», username `falar_feedback_bot`. Затем в настройках бота:
   Serverless → включить.
2. `bash bot/tg.sh status` — скрипт спросит токен CLI.
3. `bash bot/tg.sh push`, затем `bash bot/tg.sh migrate` — код и таблицы уходят в облако.
4. Напишите боту `/id`, добавьте `FALAR_BOT_OWNER=<число>` в `bot.env` и снова выполните
   `bash bot/tg.sh push`.
5. Создайте закрытую группу, включите в ней «Темы» и добавьте бота администратором с правом
   «Управление темами». Напишите в группе `/setup` — бот создаст топики. Повторный `/setup`
   ничего не ломает: он заново создаёт только удалённые топики.

Команды разработчика: `/setup` (в группе), `/id`, `/help`; ответом на сообщение — `/block`
и `/unblock`. Если разработчик пишет боту в личку сообщение с меткой, бот обрабатывает его как
сообщение от человека. Так приложение проверяется своим аккаунтом.

## Проверки

`cd bot && npm test` — проверки на столе. Вместо Bot API — заглушка, база — та же SQL на
node:sqlite, таблицы строятся из `schema.js`.

Если понадобится трекер (Linear и т. п.): исходящий HTTP есть (`fetch` из `sdk`), но хранилища
секретов в Serverless документация не описывает. Ключ можно держать так же, как `lib/owner.js`:
вне git, через `bot.env`.
